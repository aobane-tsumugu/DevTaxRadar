| 年次処理と全画面の年範囲が未統一 | 概要は対象年の全費用とAI内訳へ修正。API・根拠画面・初期設定結果は全期間の経路を保持 | 対象年の費用・採用残高・根拠を一貫させる必要がある |
| 画面分類と詳細税務coreが未接続 | `classificationView`, `src/core/taxDecision.ts` | 分類ラベルと必要事実の確認が切り離される |
| 観測品質の固定が未完了 | 年度採用版は入力・数値観測・結果を保持し、再走査と分離済み。全契約の捕捉状態とAdapter版は未完了 | 再走査や履歴消失で以前の説明を再現できなくなる |
| 相談回答の反映が未接続 | 採用版の費用・判断・残高はMarkdown/JSON出力済み。同じ対象への相談回答取り込みは未完了 | 採用記録・訂正・相談回答まで一貫した資料にする必要がある |
| 未取得状態の契約・期間別管理が不足 | 割合不明と0を分離し、readinessの一律表示は撤去。該当なし・保留・不一致は年度別に保存済み。捕捉外率は全体1値 | 推定を事実のように見せ、不要な入力を促しうる |

React、Fastify、SQLite、ローカル処理、source別増分走査、全候補の番号統合、金額保存則は活かす。全アプリの書換え、マイクロサービス化、クラウド化、LLM追加は必要条件ではない。

### 起動条件と自動化の境界

HTMLのR2には、利用開始、履歴取込、支払等の変更、開発の節目、年度採用、相談回答・訂正、翌年開始、閲覧・出力・復元の8つの起動条件を示す。各条件に実行主体、自動で進む範囲、判断待ち・失敗時の戻り先、保存される結果を対応付ける。これは完成形の責務であり、全経路の実装済み・定期実行済みを意味しない。

計算と作業入力の保存は、年度資料の採用から区別する。計算可能な別項目は進め、不足事項は対象を限定して質問する。本人確認後の採用では版・hash・前年接続・原価重複を再照合する。訂正や相談回答は同じ対象へ戻し、元版を保持して影響年を示す。閲覧や年の選択だけで採用版を書き換えない。再送・中断後の再開でも二重計上せず、同じ入力と方法版から同じ説明へ戻れることを自動化の完成条件とする。
