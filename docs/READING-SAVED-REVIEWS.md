# 保存済み年度資料を、原本や通常起動なしで読む

`data:read` は、指定したデータフォルダまたはバックアップ内の `devtax-radar.db` から、採用済み年度資料を一覧表示・出力する読取り専用コマンドです。ブラウザやAPIサーバーの起動、元履歴の再接続、走査、DB移行、復元先の作成は不要です。

通常の画面と同じ保存内容のハッシュ検証・JSON/Markdown出力処理を使います。当時の計算結果を現在のエンジンで計算し直したり、元版を後の訂正版へ差し替えたりしません。未採用の作業中入力を年度資料へ変換する機能ではありません。

## 用意するもの

Node.js 24.14以上と、このコマンドを含むDevTaxの実行版を用意します。Releaseパッケージでは追加の `npm install` は不要です。ソース版では、既存の手順で `npm ci` を済ませてから使用します。

読取り元はフォルダで指定します。DBのファイル名は `devtax-radar.db` のままにしてください。DBファイルだけを稼働中のアプリからコピーすると、WALにある記録を失う場合があります。持ち運びには既存のbackup機能を使用し、可能ならアプリを停止した保存先または検証したbackupを読みます。

この読取りではsaltや元履歴を新規生成しません。ただし、完全なバックアップとその復元には、従来どおり `identifier-salt` とmanifestを含む一式が必要です。表示できることを、復元に必要なファイルが全部そろっている証明とはしません。

## 一覧を確認する

ソース版でもRelease版でも、次の入口を使えます。引用符を付ければ空白や日本語を含むパスも指定できます。

```sh
npm run data:read -- list "DATA_OR_BACKUP_DIRECTORY"
```

標準出力のJSONには資料ID、対象年、記録日時、残高入力版、訂正元ID、前年資料ID、記録理由が含まれます。元版と訂正版をそれぞれ表示するため、読みたい資料IDを選んでください。一覧が空でも「すべて確認済み」という意味ではありません。

読取り対象はコマンド引数だけで決まります。`DEVTAX_RADAR_DATA_DIR` の設定や、通常起動時の既定のデータ保存先には切り替えません。

## 選んだ版を出力する

```sh
npm run data:read -- export "DATA_OR_BACKUP_DIRECTORY" "REVIEW_ID" json "NEW_OUTPUT_FILE.json"
npm run data:read -- export "DATA_OR_BACKUP_DIRECTORY" "REVIEW_ID" markdown "NEW_OUTPUT_FILE.md"
```

`REVIEW_ID` は一覧のIDへ置き換えます。出力先の親フォルダは先に用意し、**読取り元フォルダの外にある、新しいファイル名**を指定してください。既存ファイル・DBを上書きせず、読取り元の中へも出力しません。これはbackupへの余計なファイルの混入を防ぐためです。

JSONは保存版の全体、Markdownは説明と完全な保存JSONを含みます。旧資料に含まれていなかった費用・証拠・観測値を、現在の入力から補いません。不明額は不明のまま、確認済み0円とは別に保持します。

正常時は結果JSONを標準出力、注意書きを標準エラーへ出します。不正な引数、対象の欠落、未対応の資料形式、ハッシュ不一致、出力先の重複などは終了コード1です。検証・出力の生成が失敗した場合、成功した出力ファイルとして公開しません。

## 検証する範囲としない範囲

読取り元をSQLiteのread-only接続で開き、`quick_check` と採用済み資料の形式・ID・対象年・保存ハッシュを照合します。別のDBスキーマを現行製品へ移行する処理は呼びません。DB全体のschemaが異なっていても、対応する保存資料v1を読み取れる場合がありますが、それは**そのDBの復元や通常起動を許可した意味ではありません**。既存restoreのschema一致条件は変えていません。

このコマンドはmanifest全体・salt・すべてのバックアップファイルの照合を代行しません。backup一式の確認には既存のverifyを使用してください。

Releaseパッケージ:

```sh
npm run data:backup -- verify "BACKUP_DIRECTORY"
```

ソース版:

```sh
node --import tsx scripts/data-backup.ts verify "BACKUP_DIRECTORY"
```

SQLiteのread-only接続は記録を書き換えませんが、稼働中のWAL形式DBの読取りにはSQLiteのWAL/SHMファイルが関係します。厳密な保管コピーとして扱う場合は、通常利用中のDBではなく、自己完結した検証済みbackupを指定してください。

## 共有前の確認

出力には記録理由、相談回答、証拠メモなどの自由記述を含みます。自動匿名化済みではありません。第三者へ渡す前に内容を確認し、個人用backup一式を相談資料として渡さないでください。このコマンドは原本の回復、税務判断の検証、申告データの作成を行いません。
