# DevTax セキュリティ方針

DevTaxは、Claude Code／Codexの利用履歴を扱うローカルファーストの
Webアプリです。履歴にはプロンプト、ソースコード、ファイルパスなどの
機密情報が含まれ得ます。DevTaxを動かすPCと、利用者が明示的に選んだ
ローカルネットワーク上の共有・マウント済みフォルダを信頼境界とし、
クラウドや第三者サービスへ送信しないことを主要な境界とします。

## 保護する情報

- Claude Code／Codexの元履歴
- プロンプト、応答、ソースコード
- 絶対パス、リポジトリ名、ブランチ名
- セッションID、メッセージID
- 実際のAIサブスク支払額
- 配賦結果、税務プロファイル、確認履歴

## MVPの信頼境界

```text
ユーザーのブラウザ
      │ 127.0.0.1 + CSRF token
      ▼
DevTax local API
      ├─ 既定ローカル履歴をread onlyで走査
      ├─ 利用者が追加した共有・マウント済み履歴をread onlyで走査
      └─ 正規化したメタデータだけをローカルSQLiteへ保存
```

通常利用ではクラウドAPI、telemetry、リモートDBへ接続しません。解析のため
元履歴ファイル全体を読み取りますが、元履歴の変更、通常集計でのプロンプト本文の抽出・保存・表示、
公開デモへの実データ転用は行いません。利用者が明示的に「内容を確認」を押した場合だけ、
このPCの既定履歴の元ファイルから先頭プロンプトの短いプレビューを表示します。DBへは保存せず、
追加した共有走査元では表示しません。共有フォルダの場合、その読み取りバイトはLANを経由します。

## 実装済みの防御

- サーバーは`127.0.0.1`にだけbindする
- 更新系APIはプロセス起動ごとに生成するCSRF tokenを要求する
- ブラウザが送る`Origin`は`127.0.0.1`または`localhost`だけを許可する
- APIリクエスト本文を64 KiBに制限する
- SQLiteはOS標準のアプリデータ領域へ保存する
- 履歴中の識別子は端末内のsaltでハッシュ化する
- 追加走査元は走査元IDから別のsaltを導出し、別PCの同一セッションIDを衝突させない
- プロジェクト表示名はローカルUI向けの明示的なopt-inでのみ取得し、
  絶対パスではなく最後のフォルダ名だけを保存する
- Provider料金、未取得利用率、プロジェクト分類はCSRF保護された設定APIから
  ローカルSQLiteへ保存する
- Git管理対象と公開fixtureを`privacy:check`で検査する
- CIとテストでは合成fixtureと一時ディレクトリだけを利用する
- 追加走査元の元セッションIDと絶対パスは`session_references`へ保存しない
- 走査元が読めない、読取失敗、走査中にファイルが変化した場合は、その走査元の前回正常値を保持する

CSRF tokenは認証情報ではありません。同じユーザー権限で動作する悪意ある
ローカルプロセスからの防御は、OSのユーザー分離とファイル権限に依存します。

## 保存しない情報

正規化イベントへ保存できる項目は走査元ID、Provider、月、ハッシュ化識別子、モデル、
トークン内訳、スキーマ版、信頼度に限定します。次は保存しません。

- プロンプト／応答本文
- ソースコードやファイル内容
- 元のセッションID、メッセージID
- 元の絶対パス

追加走査元の絶対パスは、利用者が入力した接続設定として`history_sources`へ保存します。
この例外は走査元設定画面の`GET /api/sources`だけで参照し、走査結果、Dashboard、
フォルダ一覧、セッション詳細、Markdown出力へ含めません。

## 共有フォルダの境界

- SMB/Samba、Windows共有、VPN、マウントの認証と暗号化はOSと利用者のネットワーク設定に依存します
- DevTaxはLANで待受せず、共有先PCへ秘密鍵、合言葉、クライアント、常駐サービス、タスクを配置しません
- 共有先の生JSONLは走査中にLANを通過します。信頼できないLANでは、OS側で暗号化された共有またはVPNを利用してください
- 共有の作成、OS資格情報の保存、共有先PCの起動はDevTaxの責務外です

## 利用者のファイルへの書き込み

DevTaxが自分のデータフォルダの外へ書き込むのは、次の2種類だけです。どちらも画面から明示的に操作したときに限ります。

- `~/.claude/settings.json` の `cleanupPeriodDays`
- 「PCとデータ」で指定した**新しい**バックアップ先・復元先フォルダ

バックアップ先・復元先は、存在しないフォルダだけを受け付けます。同じ階層の一時フォルダへ作成してから名前を変えて公開し、既存のフォルダやファイルは上書きしません。現在のデータフォルダの中は指定できません。APIは`127.0.0.1`からのCSRFトークン付き要求だけを受け付けます。

`cleanupPeriodDays` はClaude Codeが履歴を削除するまでの日数で、税務記録に必要な履歴が消えるのを防ぐために
変更できるようにしています。次の条件をすべて満たす場合にだけ書き込みます。

1. 画面から明示的に日数を入力し、ボタンを押した場合のみ。自動では一切変更しない
2. 書き込む前に、同じ場所へ `settings.json.devtax-backup-<UTCタイムスタンプ>` として控えを取る。
   既存の控えは上書きしない（`COPYFILE_EXCL` を使い、衝突したら連番を足す）
3. JSONとして解析できない場合、オブジェクトでない場合は書き込みを中止する。
   Claude Code自身も解析に失敗するとクリーンアップを止めるため、壊れたファイルを
   上書きすると問題が二重に隠れる
4. 書き込みは同じディレクトリの一時ファイルへ行い、`rename` で置き換える。
   途中で失敗しても元のファイルはそのまま残る
5. 変更するのは `cleanupPeriodDays` キーだけで、ほかの設定は保持する

`~/.claude/projects` と `~/.codex/sessions` の履歴ファイルは読み取りのみで、書き込み・
移動・削除は一切しません。

## 取り込み時のハッシュ記録とその限界

このPCの既定履歴では、取り込んだ各履歴ファイルのSHA-256を `session_references` へ記録し、再走査時に内容が
変わっていれば件数を走査直後の画面に出します。ハッシュそのものとファイルパスはこの
テーブルの外へ出しません（APIの応答に載るのは件数だけです）。読み取りが途中で失敗した
ファイルは、部分的なハッシュを記録せず「未記録」として扱います。追加した共有走査元では
元ファイルのパスとハッシュを保存せず、走査前後のサイズ・更新日時が一致したファイルだけを採用します。

**これは第三者に対する改ざん防止ではありません。** DevTaxは利用者と同じ権限で
動くため、記録したハッシュ自体も利用者が書き換えられます。示せるのは「同じPCの中で
記録の辻褄が合い続けている」ことだけです。第三者性は、外部の時刻証明があってはじめて
生じます。

## 開発・テスト時のルール

1. 実ユーザーの`~/.claude`、`~/.codex`をfixtureへコピーしない
2. fixtureは架空の値だけで手書きする
3. DBテストでは`DEVTAX_RADAR_DATA_DIR`を一時ディレクトリへ設定する
4. サーバーテストでは`HOME`と`USERPROFILE`も一時ディレクトリへ設定する
5. ローカルラベルのテストは合成履歴を一時HOMEへコピーして行う
6. Release前にsource archiveと配布物の双方へprivacy checkを実行する
7. スクリーンショットは合成データ、またはallowlist式エクスポートだけを使う
8. 保持期間の書き換えを試すときは、`DEVTAX_RADAR_CLAUDE_SETTINGS`を一時ディレクトリへ
   コピーしたファイルへ向ける。実ユーザーの`~/.claude/settings.json`を対象にしない

## 公開デモ

公開デモを作る場合は完全な合成データを既定とします。実データから共有用
エクスポートを作る機能は、次のallowlistだけを新しいJSONへ書き出す方式にし、
元オブジェクトから危険項目を削除する方式にはしません。

- Provider
- 月
- `Product A`等の匿名名
- 丸めた利用割合または利用指数
- デモ用月額
- 税務候補と判定理由

## 脆弱性の報告

公開リポジトリで実データの混入や外部送信を発見した場合、Issueへ機密情報を
貼らないでください。リポジトリ管理者が用意する非公開の報告経路を利用して
ください。正式公開時には`SECURITY.md`の連絡先とサポート対象バージョンを
更新します。

## 現在の制約

- ローカルマルウェアや同一ユーザー権限の別プロセスは脅威モデル外
- DB暗号化は未実装であり、端末・OSのディスク暗号化に依存
- Claude Code／Codexの履歴形式変更にはAdapter更新が必要
- privacy checkは多層防御の一部であり、公開前レビューを置き換えない
- 本プロダクトは税務判断や申告結果を保証しない
