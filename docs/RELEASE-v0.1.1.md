## v0.1.0からの変更

### Codexをアーカイブしても二重計上せず、取り込んだ数値を保持

- 既定のCodex取得元は通常履歴と兄弟の`archived_sessions`を同じ取得元として走査します。既定取得元のルート名が`sessions`の場合に限る動作で、利用者が追加した取得元へ兄弟フォルダを自動追加しません。
- 同一取得元・同一セッションのコピーを合算しません。現在読める通常履歴をアーカイブより優先し、同じ種類なら更新日時と不透明ファイルキーで決定的に選びます。新しい更新日時が内容の正しさを証明するわけではありません。
- 取り込み後に原本が見えなくなっても、取込済みの数値を集計から消しません。最後まで走査した時点の原本不在と、未接続・読み取り失敗を区別します。
- 原本を再読取できた場合は、その数値へ置き換えます。以前より小さい値や0も受け入れ、古い値を足したり最大値へ固定したりしません。旧版の0利用キャッシュもセッション対応を再確認します。
- 旧DBや再接続後に原本との対応を確かめられない数値は、対応未確認として保持します。存在しない時点別明細を作らず、削除された理由も推測しません。
- 保持状態を走査結果、費用の来歴警告、数値観測記録と出力へ残します。本文プレビューも、現在原本を読める場合だけ利用できます。

### 単独請求の履歴範囲を編集できるよう修正

- 重複や期間の重なりがない請求も、契約の呼び名、履歴範囲、捕捉外割合と根拠を画面から入力できます。従来は重複候補か既存の契約対応がある請求にだけ、編集欄が表示されていました。
- 重複のない請求に重複警告は表示しません。編集だけで契約対応を確認済みにせず、入力途中・本人確認・保存の区別を保ちます。
- 単独請求の範囲指定、割合・根拠の編集、再表示時の保持、0%と不明の区別、空一覧と読取専用表示を回帰テストで確認します。

### ソフトウェア方法の整数入力を修正

- ソフトウェア方法選択画面の整数判定で、数字を正しく受け付けない正規表現を修正しました。青色申告の少額資産特例で必要な金額・月数を入力しても、方法を選べなくなる不具合を解消します。
- 適用要件や上限を緩める変更ではありません。整数・適用条件の検証と、未保存入力への反映・DB保存の区別は維持します。

### 回帰テスト・品質ゲート・説明の整合

- Codexの通常履歴・アーカイブ間の移動、原本不在、コピー、旧キャッシュ、再読取と数値保持を検証する回帰テストを追加しました。
- 本文サイズ上限のAPIテストで、リクエスト送信中に返るレスポンスも最後まで収集するよう修正しました。
- Release workflowにも`docs:check`と`format:check`を追加し、PR・`main` CIにも`release:pack`を追加しました。PR・`main` CIをUbuntuとWindowsの両方で実行する構成にし、公開前のcommitでNode/APIテストと配布ZIPの生成・ライフサイクルスモークを検査します。これはWindowsの実画面受入ではなく、remote CIの通過状況は最終commitで別途確認します。
- READMEの年払い・日数配分、契約ごとの履歴範囲と捕捉外割合、金額不明の保存、配布版と`main`の違いを現行実装に合わせました。README・CONTRIBUTINGの「format:checkは現在失敗する」という古い案内を削除しました。

## 更新時の注意

- Node.js **24.14以上**が必要です。配布ZIPは依存関係を同梱しており、展開後の`npm start`に`npm install`は不要です。
- データを保全するため、更新前に[READMEのバックアップ手順](../README.md#データの保全と復元)を確認してください。元ログ・証拠原本は別途保管してください。
- 既存の旧形式ファイルキャッシュを移行するときは、検証済みバックアップを作成してから取得状態・セッション対応の列を追加します。セッション・制作物の識別子は変更しません。
- 旧版ですでに取り込み集計から消えた未保持の数値や、最初の取り込み前に削除された履歴は、この更新だけでは復元できません。
- 原本を失っても数値を保持する機能は、会話本文のバックアップ、第三者に対する真正性の証明、税務上の証明や法定保存の保証ではありません。
- 復元は新しいデータフォルダへ行います。未対応schemaの読み捨てや、旧版への逆移行を案内するものではありません。

## 実装・受入の境界

- 請求額の日数比配分は、明細の原額を月へ分ける処理です。事業者の請求額、割引・返金、税額・為替を自動で決めません。旧月額概算は契約開始月・終了月を日割りしません。
- 不明な金額、捕捉外割合、利用時点、契約間で重複する履歴を0や推定値で埋めず、原額と未算定理由を残します。取得元の停止・過去値の利用も、捕捉外割合とは別の来歴です。
- 契約固有の範囲を指定しない単一契約は、既存の取得範囲・共通割合を使います。それだけで、その期間について本人が確認した事実とは扱いません。
- クラウド同期、複数PCからの同時編集、証拠原本の取り込み、すべての税務処理の自動確定は対象外です。
- 公開デモは合成データ専用で手動更新です。ソース・Release・公開デモの反映状態と、コード・自動テスト・実際の画面受入はそれぞれ別に確認します。
