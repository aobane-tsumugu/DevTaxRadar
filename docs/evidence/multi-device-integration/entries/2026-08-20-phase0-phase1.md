## Interpretation and alternatives

- Current explanation: Fresh clone was appropriate because PC1 was clean, its only local branch was present on the live remote, it had no tags, and commit/tree identities matched. The hub plus canonical-bundle architecture is preferred because offline and LAN delivery share exact artifact and merge semantics while the browser boundary remains loopback-only. Cross-device duplicate candidates count separately until review, preventing silent undercount.
- Competing explanations: a direct hub API would create a second data plane; peer/shared-database synchronization would widen conflicts and network filesystem risk; a plaintext or archive bundle would add avoidable confidentiality and parsing risk.
- Evidence that distinguishes them: source/storage audit, tracked-tree comparison, runtime privacy smoke, SQLite network/WAL guidance, JOSE/TLS primary sources, and deterministic merge/test requirements.

## Contemporaneous decision

- Decision at this time: PC2 is the development authority. Recommend one hub as mapping/contract/allocation authority and one signed-and-encrypted bundle as the only offline/LAN data plane. Keep browser UI loopback-only and use a separate opt-in bundle ingress.
- Action now allowed: Complete read-only design review, documentation corrections, verification, and final approval handoff.
- Action still prohibited: Product code/schema/API/network/UI implementation, PC1 edits, destructive operations, raw user-data migration, push/PR/deploy/release.
- Coverage and confidence limit: Phase 0 behavior is verified with synthetic data only. Certificate provisioning, JOSE library/profile, headless Linux key storage, suggestion thresholds, limits, and implementation remain intentionally unresolved at the approval/security gates.
- Revision trigger: A blocking fresh-review finding, user rejection/change of an approval decision, failed post-documentation gate, or any future runtime privacy/financial invariant failure.

## Corrections and later history

- The initial evidence draft included a physical home path and caused `privacy:check` to fail. It was corrected before promotion; repository evidence now uses logical placeholders.
- Automatic cross-device coalescing was withdrawn after review because two real sessions can have identical metadata. Version 1 counts both, marks the month provisional, and blocks final tax export until a user-reviewed logical contribution exists.
- The original single-session model was replaced by explicit monthly `UsageSlice` records to preserve existing month-crossing behavior and migration totals.
- The initial three-step/atomic enrollment wording was withdrawn. Enrollment now converges through signed pending, acknowledged, activation receipt, final confirmation, and active states with exact retry rules.
- On 2026-08-20, after reviewing operational frequency and maintenance cost with the user, the signed-bundle/LAN-ingress recommendation was superseded before implementation. The user explicitly approved direct read-only scanning of configured local or shared filesystem roots as the standard path. Source-side collectors, scheduled tasks, keys, and manual import/export remain optional fallback concepts rather than Phase 2 defaults. See `2026-08-20-direct-folder-pull-phase2`.
