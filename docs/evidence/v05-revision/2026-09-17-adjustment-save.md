# 2026-09-17 返金・訂正を既存の保存境界へ接続

基点: main `ac9e4ec982e1d18ed2a4cb1c20d3f0dec4afc1c0`。新しいブランチ・force push・別保存APIは作成しない。

## このコミットの製品変更

- planningの任意のsourceAdjustments一覧を、既存workspaceの版照合・一括保存・再読込みへ接続する。
- 旧要求が一覧を省略した場合、保存済み一覧を削除しない。明示的な空配列だけが削除となる。公開workspaceでは409と再読込み案内を返す。
- extensionの書込みはplanningと同じSAVEPOINT内。後段の失敗時は一緒に巻き戻る。
- 競合解決は金額・対象・期間・根拠を一つの記録として選択する。同時編集・削除を黙って合成しない。
- 直接費の発生日を確認基礎として保持できるようにし、文字列列挙に配列を渡す誤入力を拒否する。
- 旧DBは既存app_settingsを使い、テーブル移行・年度採用版の変更はしない。
