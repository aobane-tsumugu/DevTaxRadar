# W02 数値記録・取得来歴の実装と検証

日付: 2026-09-10（日本時間）
基準: main `04629ac4603a6dc60425e09d872603b9f81eb76c`

## 実装

再走査の開始前・数値の置換直前・走査後、および読み取り元の変更・削除前に、取得値とworkspace・費用計算・時間帯・取得来歴を保存する。保存先は既存SQLiteのapp_settingsで、DB schemaや同期基盤を追加しない。同一入力・取得値・来歴では保存を増やさず、日時更新やread/reusedの違いだけでも増やさない。

ファイルごとに読取・再利用・前回値使用・初回取得保留を区別し、方式版と取得値の不透明な参照を記録する。来歴は数値のhashに対応付け、途中中断等で対応できない場合は不明とする。走査完了とアカウント全利用の完全捕捉は別である。

GET /api/observations/records とGET /api/observations/records/:id、および登録状況画面から保存時点の数値を読む。現在の入力・年度採用版へ自動で戻す操作は設けない。取得来歴は新しい年度資料へ固定し、共通費用基礎の警告を通じてMarkdownにも引き継ぐ。旧年度資料を現在の来歴で補完しない。

原本パス・会話本文・生のセッションIDは数値記録に追加しない。自由記述は残るため個人用JSONと表示し、出力内容を確認できるようにする。原本保存・法定保存・税務判断の採用を代替するものではない。

## 実行した検証

Node.js 22.16.0、TypeScript 5.8.3の環境で、実装モジュールをESMへ変換し、テストの実行器のimportだけをvitestからnode:testへ置き換えて実行した。SQLite、記録・検証・来歴・Markdownの実装は実物を使用した。

`tests/server/observationRecords.test.ts`: 15件成功、0件失敗。明示的な項目抽出、変更前記録の保持、時間帯、取得来歴と数値の対応、前回値と初回未取得の区別、同一状態の抑制、破損記録、ページ送り、SQLite VACUUM INTO後の別保存先からの読取り、未知と0の区別、注入したDB書込失敗時のrollback、停止中の取得元、保存済みMarkdownの来歴を検査した。

変更したTypeScript/TSXの構文検査も実施した。これはtranspileによる構文確認であり、プロジェクト全体の型検査ではない。
